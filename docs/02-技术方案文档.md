## 1. 总体架构

### 1.1 架构概览
系统采用前后端分离的三端架构：微信小程序（学生端）、React Web 管理后台、Spring Boot 后端服务，统一通过 Nginx 网关接入，存储层使用 MySQL + Redis + OSS。

### 1.2 模块划分
| 层 | 模块 | 职责 |
|----|------|------|
| 学生端 | 微信原生小程序 | 刷题、复习、小测、报告、订阅 |
| 后台前端 | React SPA | 题库管理、学习看板、运营配置 |
| 后端服务 | Spring Boot 多模块 | 学生服务、管理服务、支付运营服务 |
| 存储 | MySQL + Redis + OSS | 业务数据、缓存、题目资源 |

## 4. 关键技术设计

### 4.1 鉴权方案
- **小程序**：`wx.login` → 后端 `code2session` → 返回自定义 token（JWT），存 storage；后续请求带 Authorization。
- **后台**：账号密码登录 → Spring Security 校验 → JWT；RBAC 控制（管理员/教师）。

### 4.2 掌握度计算
- 每题维护 `mastery_level`（0 未掌握 / 1 部分 / 2 已掌握）与 `next_review_at`。
- 答对：连续答对次数 +1；满 2 次升档、重置复习日 +7 天。
- 答错：归零、降为未掌握、复习日 +1 天。
- Redis 缓存热点学生掌握度，定时落库。

### 4.3 错因归因
- 错因枚举：`KNOWLEDGE_MISSING` / `CONCEPT_CONFUSED` / `QUESTION_TRAP`。
- 答错后小程序弹层让学生选择，写入 `wrong_record`；后台据此生成归因分布。
- 同题第二次答错，强制弹出变式题 1~2 道。

### 4.4 限时小测
- `quiz_schedule` 配置开考时间；XXL-Job 触发"开考/截止"。
- 学生进入小测：后端按规则组卷并生成 `quiz_session`，一次性下发题目。
- 提交后批改，写 `quiz_result`、更新掌握度。

### 4.5 间隔复习队列
- 每日 Job 扫描 `next_review_at <= today` 的题，生成复习队列。
- 小程序"复习"页拉取队列，答完更新掌握度。

### 4.6 微信支付
- 下单 → 调用微信支付统一下单 → 返回 `prepay_id` → 小程序 `wx.requestPayment`。
- 支付回调验签 → 写订阅记录 → 开通权益。
- 续费：到期前 3 天推送订阅消息提醒。

## 5. 部署拓扑

| 组件 | 部署 | 说明 |
|------|------|------|
| Nginx | 单机 / SLB | TLS、反向代理、后台静态资源 |

| MySQL | RDS 主从 | 主从读写分离 |
| Redis | 云 Redis | 单实例即可 |
| OSS | 对象存储 | 题目图片、导入文件 |
| 小程序 | 微信平台 | 提审后发布 |

## 6. 非功能与约束
| 项 | 目标 |
|----|------|
| 响应 | 普通接口 P95 < 300ms；批改 < 1s |
| 并发 | 支持 1k 并发答题 |
| 可用性 | 小程序 99.5% / 后台 99% |
| 安全 | HTTPS 全站、密钥配置化、后台 RBAC、支付走官方 |
| 数据 | 每日全量+增量备份；学生数据脱敏 |

## 7. 风险与对策
| 风险 | 对策 |
|------|------|
| 微信审核驳回（学科类目） | 提前确认类目与资质；内容合规审查 |
| 题库录入工作量大 | 后台支持 JSON 批量导入；后续考虑 AI 辅助解析 |
| 掌握度计算性能 | Redis 缓存 + 异步落库 |
| 支付对账 | 每日对账 Job，异常告警 |
