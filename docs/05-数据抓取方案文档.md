## 1. 合规边界与原则

### 1.1 版权红线
中考真题的著作权通常归属**各地教育考试院/命题机构**，未经授权商业使用存在侵权风险。本方案严格遵循：

| 来源类型 | 是否采用 | 说明 |
|----------|----------|------|
| 各地市教育考试院历年真题原文 | ❌ 不直接抓取 | 版权属于命题机构 |
| 教辅出版社题库（如人教、浙教等） | ❌ 不抓取 | 商业版权 |
| 付费教育平台题库（学科网等） | ❌ 不抓取 | 商业版权 |
| GitHub 上 CC0 / MIT / CC-BY 协议的开源题库 | ✅ 优先采用 | 协议允许使用，需署名 |
| 教师原创 / 教研员授权投稿 | ✅ 自建 | 自有版权 |
| 公有领域史料（古籍、正史、政府公文等）改编题 | ✅ 可用 | 改编需标注史料出处 |
| 用户UGC（标注 CC-BY-SA） | ✅ 谨慎采用 | 需审核 + 署名 + 留存授权证据 |

### 1.2 五条铁律
1. **不抓付费墙后的内容**（即使技术上可行）。
2. **不抓明确禁止爬取的站点**（看 robots.txt + ToS）。
3. **每道题必须可追溯到来源**：`source_type` + `source_url` + `license` + `author`。
4. **开源协议优先级**：CC0 > CC-BY > CC-BY-SA > MIT > 自创。
5. **存疑不采**：来源协议不明的，一律不进生产库。

### 1.3 开源策略
- 抓取脚本与清洗脚本：MIT 协议开源至仓库 `tools/scraper/`。
- 整理后的题库数据：CC-BY-SA 4.0 协议开源至仓库 `data/question-bank/`。
- 每道题保留 `license` 字段，便于二次分发合规。

## 2. 候选数据源（调研方向）

> ⚠️ 以下为调研方向，具体项目可用性需在抓取前**逐一核对协议原文**，符合方可采用。

### 2.1 开源代码托管平台
- **GitHub**：检索关键词如 `中考 历史 题库`、`middle-school history quiz`；筛选 LICENSE 为 MIT/Apache/CC0 的仓库。
- **Gitee**：同上，国内镜像更稳定。
- **GitLab / Codeberg**：教育类公益项目。

### 2.2 公益教育资源平台
- 国家中小学智慧教育平台（公开课件，**仅可引用知识点，不抓题目**）。
- 各省电教馆公开微课（同上，仅引用知识点）。
- 维基百科 / 维基文库（公有领域史料，**仅用于改编题干，不直接搬运题目**）。

### 2.3 自建渠道（主力，推荐 ≥ 60% 题量）
- 教师原创投稿：与初中历史教师合作，签署授权。
- 教研员审校题：基于史料改编，标注出处。
- 历史题改编：以公有领域史料为题干素材重新命题。

### 2.4 不采用的来源
- 百度文库、豆丁等用户上传未授权文档。
- 微信公众号付费合集。
- 任何"中考真题汇总"商业站点。

## 3. 题库 JSON Schema

### 3.1 单题结构
```json
{
  "externalId": "HIS-2024-001",
  "subject": "HISTORY",
  "type": "SINGLE_CHOICE",
  "stem": "秦始皇统一六国的年份是？",
  "stemImage": null,
  "options": [
    { "key": "A", "content": "公元前221年" },
    { "key": "B", "content": "公元前206年" },
    { "key": "C", "content": "公元220年" },
    { "key": "D", "content": "公元618年" }
  ],
  "answer": "A",
  "analysis": "公元前221年，秦王嬴政统一六国，建立秦朝。",
  "knowledgeIds": ["K-CHN-ANC-QIN"],
  "primaryKnowledgeId": "K-CHN-ANC-QIN",
  "difficulty": 2,
  "sourceType": "ORIGINAL",
  "sourceYear": null,
  "sourceDesc": "教师原创",
  "sourceUrl": null,
  "author": "张老师",
  "license": "CC-BY-SA-4.0",
  "variantExternalIds": ["HIS-2024-002"],
  "variantRelationType": "VARIANT",
  "tags": ["高频", "秦汉史"]
}
```

### 3.2 字段对照表（→ 03 数据库）
| JSON 字段 | 数据库字段 | 说明 |
|-----------|------------|------|
| externalId | external_id | 抓取侧唯一 ID，用于去重 |
| type | question.type | SINGLE_CHOICE→1, TRUE_FALSE→2 |
| stem / stemImage | question.stem | 图片转 OSS url |
| options | question_option | 批量插入 |
| answer | question.answer | |
| knowledgeIds | question_knowledge | |
| primaryKnowledgeId | question_knowledge.is_primary | |
| difficulty | question.difficulty | |
| sourceType | question.source_type | ORIGINAL / PAST_EXAM_ADAPTED |
| license / author / sourceUrl | question 新增字段 | |

### 3.3 文件命名
```
data/question-bank/
├── history/
│   ├── 2026-09-17-github-xxx.json
│   ├── 2026-09-17-teacher-original.json
│   └── manifest.json          # 清单：文件、题数、协议、来源
```

## 4. 数据库扩展

### 4.1 question 表新增字段（版权追溯）
| 字段 | 类型 | 说明 |
|------|------|------|
| external_id | VARCHAR(64) | 抓取侧唯一 ID，唯一索引 |
| license | VARCHAR(32) | CC-BY-SA-4.0 / MIT / ORIGINAL |
| author | VARCHAR(64) | 原作者/投稿人 |
| source_url | VARCHAR(255) | 来源链接，可空 |
| source_type | TINYINT | 扩展枚举：1 真题原文(禁用) 2 真题改编 3 模拟 4 原创 5 开源搬运 |

> ✅ 03 文档的 `source_type` 语义扩展为上表，避免直接采用"真题原文"。

### 4.2 去重策略
- 入库前按 `external_id` 唯一约束去重。
- 无 external_id 的自建题，用 `(stem 摘要 hash)` 二次去重。
- 题干相似度 > 0.92（MinHash）转人工审核。

## 5. 抓取工程

### 5.1 技术选型
| 模块 | 选型 | 说明 |
|------|------|------|
| 语言 | Python 3.11 | 爬虫生态成熟 |
| HTTP | httpx | 支持 async |
| 解析 | parsel / selectolax | HTML 解析 |
| 去重 | datasketch（MinHash） | 题干相似去重 |
| 校验 | pydantic v2 | JSON Schema 校验 |
| 任务 | APScheduler 或手动 | 一次性 + 增量 |
| 存储 | 本地 JSON + SQLite 索引 | 便于版本化 |

### 5.2 目录结构
```
tools/scraper/
├── README.md
├── pyproject.toml
├── src/
│   ├── sources/                # 各来源适配器
│   │   ├── base.py            # 抽象 Source
│   │   ├── github_source.py
│   │   └── teacher_upload.py
│   ├── cleaners/              # 清洗与标准化
│   ├── dedup.py               # MinHash 去重
│   ├── validator.py          # Pydantic Schema
│   ├── knowledge_mapper.py   # 考点映射
│   └── exporter.py           # 导出 JSON
├── tests/
└── data/                       # 输出目录（gitignored 大文件，仅保留样本）
```

### 5.3 流程
```
1. 拉取候选源 (robots.txt 校验)
   → 2. 解析原始题目
   → 3. 协议校验（license 必须存在且合规）
   → 4. 清洗标准化为 Schema
   → 5. MinHash 去重
   → 6. 考点映射（人工辅助 + 关键词规则）
   → 7. Pydantic 校验
   → 8. 导出 JSON + manifest.json
   → 9. 人工抽审（≥10%）
   → 10. 通过后台 /api/admin/question/import 导入
```

### 5.4 协议校验规则
```python
ALLOWED_LICENSES = {"CC0", "CC-BY-4.0", "CC-BY-SA-4.0", "MIT", "Apache-2.0", "ORIGINAL"}
assert question["license"] in ALLOWED_LICENSES
assert question["sourceType"] != "PAST_EXAM_RAW"  # 禁用真题原文
assert question.get("author") or question.get("sourceUrl")
```

### 6.2 映射规则
- 关键词规则：题干/解析包含 "丝绸之路" → SUI-TANG 等子考点。

- 一题可映射多考点，但必须标 `primaryKnowledgeId`。

## 8. 质量与审核

### 8.1 自动校验
- Schema 校验：必填字段、选项 key 合法、答案在选项中。
- 重复校验：MinHash 相似度。
- 考点校验：至少 1 个有效 knowledgeId。
- 政治与事实校验：解析中关键史实年份/人物自动比对（自建事实库）。

### 8.2 人工抽审
- 每 100 题抽 10 题人工复核。
- 复核维度：史实正确、解析清晰、考点准确、政治合规。
- 不通过者回退或下架。

### 8.3 内容合规
- 涉及领土、民族、近现代史的表述，遵循教育部审定统编教材口径。
- 敏感事件不命题或交教研组审定。

## 9. 导入与上线

### 9.1 导入流程
1. 抓取脚本产出 `history/*.json` + `manifest.json`。
2. 提 PR 至仓库，CI 跑 Schema + 去重 + 单元测试。
3. 合并后由管理员在后台 `POST /api/admin/question/import` 上传 JSON。
4. 接口返回 `{ inserted, skipped, conflicted }`，冲突项（external_id 已存在）跳过。
5. 上架前 `status=审核中`，审核通过后 `status=上架`。

### 9.2 版本化与回滚
- 题库 JSON 文件按日期版本化提交至 Git。
- 导入操作记录 `question_import_log`。
- 支持按 import_log 回滚该批次（软删该批次题目）。

## 10. 风险与对策

| 风险 | 对策 |
|------|------|
| 开源题库协议误判 | 每个来源逐字核对 LICENSE 文件，存档截图 |
| 题干历史事实错误 | 事实校验库 + 教研员复核 |
| 题量不足 300 | 自建为主力，分阶段达成 |
| 抓取被反爬 | 优先采用 API/开源仓库，不爬商业站点 |
| 版权追责 | 保留 license/author/source_url 全链路证据；上线版权投诉入口 |
