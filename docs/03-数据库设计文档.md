## 1. 设计约定
- 主键：`id` BIGINT UNSIGNED AUTO_INCREMENT。
- 审计字段：所有业务表含 `created_at` / `updated_at` / `deleted`（TINYINT，0 未删 1 已删，软删）。
- 时间：`DATETIME`，存 UTC+8。
- 布尔：TINYINT(1)，0/1。
- 命名：表 `snake_case` 单数；索引 `idx_表名简写_字段`；外键 `fk_...`（实际不建物理外键，仅逻辑关联，便于分库与性能）。
- ID 字段传前端使用字符串，避免 JS 精度丢失。

## 4. 缓存设计（Redis）
| Key 前缀 | 用途 | TTL |
|----------|------|-----|
| `student:token:{token}` | 登录态 student_id | 7d |
| `admin:token:{token}` | 后台登录态 | 2h |
| `student:mastery:{sid}` | 掌握度热点缓存 | 1h |
| `question:hot` | 热门题目 id 列表 | 10m |
| `quiz:session:{sid}` | 小测进行中会话 | 至 end_at |
| `rate:login:{ip}` | 登录限流 | 1m |

## 5. 数据量与分库预估
| 表 | 单期预估 | 增长 |
|----|----------|------|
| student | 1k | 缓增 |
| question | 300+ | 多科目后 1k+ |
| train_record | 每学生日均 50 → 5w/天 | 月 150w |
| wrong_record | train_record 30% | 月 45w |
| mastery | student × question ≈ 30w | 缓增 |

**冷热分离**：`train_record` / `quiz_result_detail` 6 个月前归档至历史表。
