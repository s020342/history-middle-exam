## 1. 部署架构

### 1.1 整体拓扑
Nginx（Keepalived + VIP 双机热备）作为统一入口，反代至 2 台 Spring Boot 应用实例（滚动更新），后端依赖 MySQL 主从 + Redis + Harbor + OSS/MinIO。

### 1.2 部署单元
| 单元 | 部署形态 | 数量 | 说明 |
|------|----------|------|------|
| Nginx | 物理机/SLB + Keepalived | 2（主备） | TLS、反代、限流 |
| Spring Boot 应用 | Docker 单镜像 | 2 实例（滚动更新） | 单体聚合，含 student/admin/pay/job |
| MySQL | RDS 或自建主从 | 1 主 1 从 | 主写从读 |
| Redis | 云 Redis 或自建 | 1 主 1 从 | 缓存与会话 |
| Harbor | Docker compose | 1 | 镜像仓库 |
| OSS/MinIO | 云 OSS 或自建 | 1 | 资源存储 |
| Jenkins Master | 物理机/Docker | 1 | 流水线调度 |
| Jenkins Agent | 多标签节点 | 6 | 见 06 文档 18.9 |

## 5. SSH 部署脚本

### 5.1 deploy.sh（统一入口）
```bash
#!/usr/bin/env bash
# 用法: deploy.sh <image:tag> <branch> [rollback_tag]
# 分支白名单
set -euo pipefail

IMAGE_TAG="${1:?missing image:tag}"
BRANCH="${2:?missing branch}"
ACTION="${3:-deploy}"
APP_DIR="/opt/history-exam"
APP_NAME="history-exam-server"
PORT=8080
SERVERS=("10.0.0.11" "10.0.0.12")

# 滚动部署：逐台更新，健康检查通过再继续
deploy_one() {
  local host=$1
  echo "[deploy] $host start"
  ssh -o StrictHostKeyChecking=no deployer@$host "
    set -euo pipefail
    docker login harbor.example.com -u \$HARBOR_USER -p \$HARBOR_PASS
    docker pull $IMAGE_TAG
    docker stop $APP_NAME || true
    docker rm $APP_NAME || true
    docker run -d --name $APP_NAME \
      --network host \
      --restart unless-stopped \
      -v /etc/localtime:/etc/localtime:ro \
      -v $APP_DIR/logs:/app/logs \
      -v $APP_DIR/config:/app/config:ro \
      -e SPRING_PROFILES_ACTIVE=$BRANCH \
      $IMAGE_TAG
    sleep 8
    curl -fsS http://127.0.0.1:$PORT/actuator/health | grep UP
  "
  echo "[deploy] $host done"
}

# 健康检查失败则回滚单台
rollback_one() {
  local host=$1; local tag=$2
  ssh deployer@$host "
    docker stop $APP_NAME || true; docker rm $APP_NAME || true
    docker run -d --name $APP_NAME --network host \
      -v /etc/localtime:/etc/localtime:ro \
      -v $APP_DIR/logs:/app/logs \
      -v $APP_DIR/config:/app/config:ro \
      -e SPRING_PROFILES_ACTIVE=$BRANCH $tag
  "
}

case $ACTION in
  deploy)
    for host in "${SERVERS[@]}"; do deploy_one $host || { rollback_one $host <prev>; exit 1; }; done ;;
  rollback)
    ROLLBACK_TAG="${3:?missing rollback tag}"
    for host in "${SERVERS[@]}"; do rollback_one $host $ROLLBACK_TAG; done ;;
  *) echo "unknown action: $ACTION"; exit 1 ;;
esac
```

### 5.2 前后台一致性
- 部署脚本在 deployer 节点（`label='deploy'`）执行，仅 release/main 触发。
- 滚动更新期间 Nginx upstream 探测剔除故障节点，避免 502。
- 部署失败：自动回滚当前节点至上一稳定 tag（从 Harbor 拉取 manifest）。

### 5.3 Nginx upstream 配置
```nginx
upstream history_backend {
  server 10.0.0.11:8080 max_fails=3 fail_timeout=10s;
  server 10.0.0.12:8080 max_fails=3 fail_timeout=10s;
  keepalive 32;
}
server {
  listen 443 ssl http2;
  server_name api.example.com;
  ssl_certificate /etc/nginx/ssl/fullchain.pem;
  ssl_certificate_key /etc/nginx/ssl/privkey.pem;

  # 后台静态
  location /admin/ {
    alias /usr/share/nginx/html/admin/;
    try_files $uri $uri/ /admin/index.html;
  }
  # 学生端 API
  location /api/student/ { proxy_pass http://history_backend; }
  # 后台 API
  location /api/admin/   { proxy_pass http://history_backend; }
  # 支付回调
  location /api/student/subscription/callback {
    proxy_pass http://history_backend;
    proxy_set_header X-Real-IP $remote_addr;
  }
}
```

## 6. Jenkins 部署流水线

### 6.1 流水线（接 06 文档 18 节）
```groovy
stage('Build & Push') {
  agent { label 'jdk17' }
  steps {
    sh 'mvn -B clean package -DskipTests'
    sh 'docker build -t $IMAGE:$TAG .'
    withCredentials([usernamePassword('harbor-push')]) {
      sh 'docker login harbor.example.com -u $HARBOR_USER -p $HARBOR_PASS'
      sh 'docker push $IMAGE:$TAG'
    }
  }
}
stage('Deploy Test') {
  agent { label 'deploy' }
  when { branch 'develop' }
  steps { sh "/opt/deploy/scripts/deploy.sh $IMAGE:$TAG test" }
}
stage('Deploy Prod') {
  agent { label 'deploy' }
  when { branch 'main' }
  steps {
    input '确认部署生产?'
    sh "/opt/deploy/scripts/deploy.sh $IMAGE:$TAG prod"
  }
}
stage('Rollback') {
  agent { label 'deploy' }
  when { expression { params.ROLLBACK == true } }
  steps { sh "/opt/deploy/scripts/deploy.sh $IMAGE:$TAG prod rollback $PREV_TAG" }
}
```

### 6.2 部署前校验
- 必须通过 07 文档 Release Gate。
- 必须有当次 changelog。
- 生产部署窗口：工作日 10:00-16:00，避免小测时段。

## 8. 数据库与缓存部署

### 8.1 MySQL（主从）
```ini
# my.cnf 关键参数
[mysqld]
character-set-server=utf8mb4
collation-server=utf8mb4_0900_ai_ci
innodb_buffer_pool_size=8G
innodb_log_file_size=512M
binlog_format=ROW
gtid_mode=ON
enforce_gtid_consistency=ON
```
- 主从通过 GTID 自动同步。
- 每日 03:00 全量逻辑备份 + binlog 增量，保留 7 天。

### 8.2 Redis
- 开启 AOF + RDB 双持久化。
- maxmemory 2GB，allkeys-lru。
- requirepass + bind 内网。

> ⚠️ **Redisson 密码配置坑（本地/测试环境踩过）**
>
> `application.yml` 中 `spring.data.redis.password: ${REDIS_PASSWORD:}` 的空串默认值是坑：当 `REDIS_PASSWORD` 未设置时，该值解析为**空字符串 `""`**（而非 `null`）。Redisson 自动配置（`redisson-spring-boot-starter`）会把这个空串当作密码向 Redis 发送 `AUTH ""` 命令，导致：
>
> - 若 Redis **未设** `requirepass`：报错 `ERR Client sent AUTH, but no password is set`；
> - 若 Redis **设了** `requirepass`：报错 `WRONGPASS invalid username-password pair`。
>
> 两种情况都会触发 `RedisConnectionException: Unable to connect to Redis server`，启动失败。
>
> **正确做法**：
> 1. 本地开发：Redis 必须显式设置 `requirepass`，启动后端时同步传 `REDIS_PASSWORD=<同 requirepass>`；或者在 `application-dev.yml` 中显式把 `password` 设为 `null`。
> 2. 测试/生产：由 Jenkins `withCredentials` 注入 `REDIS_PASSWORD`，确保容器启动时该变量非空。
> 3. 排查方向：启动异常里只要出现 `ERR Client sent AUTH` 或 `WRONGPASS`，**先核对 Redisson 实际生效的 password 配置**（可能来自 `spring.data.redis.password`、`redisson.password`、`singleServerConfig.password` 或自定义 `RedissonClient` Bean），不要误判为网络不通。


### 8.3 OSS / MinIO

- 公共读：仅 `question-images` 内含 CDN 域名图片。

## 12. 回滚流程

### 12.1 应用回滚
1. Jenkins 触发 `Rollback` stage，传入上一稳定 tag。
2. `deploy.sh rollback <tag>` 逐台切回旧镜像。
3. 验证健康检查通过。

### 12.2 数据回滚
- 仅题库导入支持按 `question_import_log` 批次软删回滚。
- 业务数据（订单、训练记录）禁止 DDL 回滚，需通过修复脚本正向恢复。
- 灾难场景：从 binlog point-in-time 恢复至故障前时间点。

## 13. Nginx 高可用（Keepalived + VIP）

### 13.1 拓扑
公网 DNS → VIP 10.0.0.9 → Keepalived MASTER/BACKUP（nginx-1/nginx-2）→ upstream app-1/app-2。

### 13.2 Keepalived 配置（MASTER 端 nginx-1）
```bash
# /etc/keepalived/keepalived.conf
vrrp_script chk_nginx {
  script "/etc/keepalived/check_nginx.sh"
  interval 2
  weight -20
  fall 2
  rise 1
}

vrrp_instance VI_1 {
  state MASTER
  interface eth0
  virtual_router_id 51
  priority 100
  advert_int 1
  authentication {
    auth_type PASS
    auth_pass <强密码>
  }
  virtual_ipaddress {
    10.0.0.9/24
  }
  track_script { chk_nginx }
}
```

BACKUP 端配置：`state BACKUP`、`priority 90`，其余相同。

### 13.3 健康检查脚本
```bash
# /etc/keepalived/check_nginx.sh
#!/usr/bin/env bash
# 检测 nginx 进程存活，失败则让出 VIP
if ! pgrep -x nginx > /dev/null; then
  systemctl stop nginx
  exit 1
fi
exit 0
```

### 13.4 脑裂防护
- 防火墙放行 VRRP 协议（协议号 112）。
- BACKUP 收到 ≥ 3 个优先级更高的广告才接管，避免网络抖动误切。
- 配置监控：Keepalived 状态变更立即告警至运维群。

### 13.5 upstream 串联
Nginx upstream 中 app 实例需配置健康探测（见 5.3 节），VIP 漂移 + upstream 探测双保险：单 nginx 宕机走 VIP 漂移，单 app 宕机走 upstream 剔除。
