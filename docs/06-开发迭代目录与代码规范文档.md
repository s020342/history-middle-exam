## 第二部分：代码规范

### 8. 通用规范
1. 变量、函数、类名使用英文，见名知意。
2. 复杂代码片段必须有注释。
3. **每个方法/函数前都要写注释**（说明用途、参数、返回）。
4. 不臆想功能实现细节，按文档与原型开发。
5. 去除无用代码和注释，不留 TODO 占位。

### 9. 命名规范

#### 9.1 通用
| 类型 | 风格 | 示例 |
|------|------|------|
| 类 | PascalCase | `QuestionService` |
| 函数/方法 | camelCase（前端）/ lowerCamelCase（后端） | `getQuestionById` |
| 变量 | camelCase | `questionList` |
| 常量 | UPPER_SNAKE | `MAX_RETRY` |
| 私有 | 前缀 `_` 或 `#` | `_init()` |
| 布尔 | is/has/can 前缀 | `isCorrect`、`hasSubscription` |

#### 9.2 后端 Java
- 包名：`com.history.exam.{module}.{layer}`，如 `com.history.exam.student.service`。
- 类后缀：Controller / Service /ServiceImpl / Mapper / DTO / VO / Entity。
- 接口与实现分离：`QuestionService` + `QuestionServiceImpl`。
- DTO（入参）/ VO（出参）/ Entity（表）严格区分。

#### 9.3 小程序 JS
- 页面文件小写连字符：`wrong-book`。
- 组件名小写连字符：`mastery-bar`。
- 事件 handler 以 `on` 开头：`onAnswerTap`。
- data 字段 camelCase。

#### 9.4 React TS
- 组件文件 PascalCase：`QuestionCard.tsx`。
- 接口前缀 `I` 省略，直接 `Question` 类型。
- hooks 前缀 `use`：`useStudentList`。

### 10. 注释规范

#### 10.1 Java（后端）
```java
/**
 * 根据考点与题型组卷
 * @param knowledgeId 考点 ID，可为空
 * @param type 题型 1 选择 2 判断
 * @param count 题量
 * @return 题目列表
 */
public List<QuestionVO> buildQuestions(Long knowledgeId, Integer type, int count) { ... }
```
- 类级注释说明职责；方法级必须写；复杂逻辑行内注释。

#### 10.2 JS / TS（前端）
```javascript
/**
 * 提交单题答案并获取批改结果
 * @param {Object} payload - { sessionId, questionId, userAnswer, durationMs }
 * @returns {Promise<Object>} 批改结果与掌握度
 */
async function submitAnswer(payload) { ... }
```

#### 10.3 SQL
- 复杂 SQL 必须有注释说明意图。
- 索引变更需说明原因。

### 11. Git 规范

#### 11.1 分支
| 分支 | 用途 |
|------|------|
| main | 生产分支，保护 |
| develop | 集成分支 |
| feature/* | 功能分支，如 `feature/train-answer` |
| fix/* | 修复分支 |
| release/* | 发布分支 |

#### 11.2 Commit Message
格式：`<type>(<scope>): <subject>`
- type：feat / fix / docs / style / refactor / test / chore / perf
- 示例：`feat(student): 训练答题流式批改`

#### 11.3 PR
- 必须 link issue。
- 至少 1 人 review。
- CI 通过方可合并。

### 12. 接口规范
- RESTful 风格，资源名复数。
- GET 查询用 query，POST/PUT 用 body。
- 统一响应 `{code, message, data}`。
- 错误码见 04 文档。
- 接口变更必须更新 04 文档与 OpenAPI 注解。

---

### 13. 数据库规范
- 不使用物理外键（性能与演进）。
- 所有业务表含 `created_at` / `updated_at` / `deleted`。
- 查询禁止 `SELECT *`，明确字段。
- 大字段（TEXT）单独查询。
- 索引命名 `idx_表简_字段`，唯一索引 `uk_`。

---

### 14. 前端规范

#### 14.1 小程序
- 分包：主包仅首页/我的/登录，训练/小测/报告拆分包。
- 列表虚拟滚动（长列表）。
- 图片懒加载，OSS 走 CDN。
- setData 最小化，避免大对象。

#### 14.2 React 后台
- 路由懒加载。
- 请求统一走 `api/` 封装，禁止组件内裸用 axios。
- 表单使用 Antd Form，校验必填项统一提示。
- 权限路由：无权限跳 403。

---

### 15. 安全规范
- 密钥（微信支付、JWT、OSS）走环境变量，禁止入库。
- 学生数据脱敏展示（手机号、openid）。
- 后台 RBAC + 操作日志（题库变更、订阅配置）。
- SQL 预编译，禁止字符串拼接。
- XSS：前端输出转义，后端入库过滤。

---

### 16. 测试规范
- 后端：Service 层单元测试覆盖 ≥ 70%，Controller 集成测试关键链路。
- 前端：核心组件快照测试，关键流程 E2E。
- 抓取：Pydantic 校验 + 去重单元测试。
- 详见 07 测试文档。

## 18. CI/CD 规范（Jenkins）

### 18.1 流水线总览
采用 Jenkins 多分支流水线（Multibranch Pipeline），按仓库分支自动触发：

| 分支 | 触发 | 流水线 | 部署目标 |
|------|------|--------|----------|
| feature/* | PR 创建/更新 | build + test | — |
| develop | 合并 | build + test + sonar + 镜像构建 | 测试环境 |
| release/* | 手动 | build + test + 镜像构建 + 推送 | 预发环境 |
| main | 合并/打 tag | build + test + 镜像构建 + 推送 + 部署 | 生产环境 |

### 18.2 工具链
| 环节 | 工具 | 说明 |
|------|------|------|
| 代码拉取 | Git Plugin | 配置 SSH 凭据 |
| 构建（后端） | Maven/JDK 17 | `mvn clean package -DskipTests` |
| 构建（前端） | Node 18 + pnpm | 小程序用 npm，后台用 pnpm |
| 构建（小程序） | miniprogram-ci | 体验版/预览上传 |
| 单元测试 | JUnit5 + Jacoco | 后端覆盖率报告 |
| 静态扫描 | SonarQube Scanner | 质量门禁 |
| 镜像 | Docker + Harbor | 统一镜像仓库 |
| 部署 | SSH 脚本 | 单体聚合部署 |
| 通知 | 企业微信/飞书 Webhook | 构建结果通知 |

### 18.3 Jenkinsfile 结构（后端）
```groovy
pipeline {
  agent { label 'jdk17' }
  options { timestamps(); timeout(time: 30, unit: 'MINUTES') }
  environment {
    IMAGE = "harbor.example.com/history-exam/server"
    TAG   = "${env.BRANCH_NAME}-${env.BUILD_NUMBER}"
  }
  stages {
    stage('Checkout') { steps { checkout scm } }
    stage('Build')    { steps { sh 'mvn -B clean package -DskipTests' } }
    stage('Test')     { steps { sh 'mvn test' } 
                       post { always { jacoco(); junit '**/surefire-reports/*.xml' } } }
    stage('Sonar')    { steps { sh "sonar-scanner" } }
    stage('Docker')   { steps { sh "docker build -t $IMAGE:$TAG . && docker push $IMAGE:$TAG" } }
    stage('Deploy') {
      when { anyOf { branch 'develop'; branch 'main' } }
      steps { sh "./deploy/scripts/deploy.sh $IMAGE:$TAG $BRANCH_NAME" }
    }
  }
  post {
    success { setBuildStatus('✅ 构建成功') }
    failure { setBuildStatus('❌ 构建失败') }
  }
}
```

### 18.4 小程序上传流水线
- 使用微信官方 `miniprogram-ci`，凭据存 Jenkins Credentials（`MP_APPID`、`MP_KEY`、`MP_IV`）。
- develop 分支：生成体验版二维码。
- release/main：调用 `ci.upload()` 上传预览版，并在管理后台通知审核。

### 18.5 质量门禁
- 单元测试通过率 100%。
- Jacoco 覆盖率 ≥ 70%（后端 Service 层）。
- SonarQube：Critical/Blocker 问题 = 0，新增代码覆盖率 ≥ 80%。
- 任意门禁失败则流水线中止，禁止合并。

### 18.6 凭据与密钥
- 所有密钥（微信支付、OSS、Harbor、Sonar Token、小程序上传密钥）必须存 Jenkins Credentials，禁止硬编码。
- 使用 `withCredentials([...])` 注入环境变量，构建日志自动脱敏。

### 18.7 制品与回滚
- 每次构建产出制品：Docker 镜像 tag + Sonar 报告 + Jacoco 报告。
- 部署脚本 `deploy.sh` 接收镜像 tag，按 tag 滚动更新。
- 回滚：`deploy.sh rollback <tag>` 切换至上一个稳定镜像。

### 18.8 通知
- 构建结果通过 Webhook 推送企业微信/飞书群。
- 通知内容：仓库、分支、提交人、构建号、结果、报告链接、回滚入口。

### 18.9 Jenkins Agent 节点规划

按构建栈分标签（label），流水线 `agent { label 'xxx' }` 按需调度，避免环境冲突。

| 节点 | 标签 | 工具链 | 用途 | 数量 |
|------|------|--------|------|------|
| jdk17-builder | `jdk17` | JDK17 + Maven3.9 + Docker | 后端构建/测试/Sonar/镜像 | 2 |
| node18-builder | `node18` | Node18 + pnpm8 + miniprogram-ci | React 后台 + 小程序上传 | 2 |
| python311-builder | `python311` | Python3.11 + uv | 抓取脚本测试与题库校验 | 1 |
| deployer | `deploy` | SSH client + Ansible-core | 生产/预发部署专用（仅 release/main 可用） | 1 |

#### 18.9.1 节点配置约定
- 物理机或云主机部署 `agent.jar`，通过 JNLP4 连接 Master。
- 每个 builder 节点磁盘 ≥ 100GB（Maven 仓库、Docker 镜像层、pnpm store）。
- 内存：jdk17/node18 节点 ≥ 8GB；deployer ≥ 2GB。
- 同标签多节点时由 Jenkins 内置负载均衡（轮询 + idle）调度。
- deployer 节点仅授权 `release/*` 与 `main` 流水线，且需人工审批（stage 前置 `input`）。

#### 18.9.2 标签使用示例
```groovy
// 后端流水线
agent { label 'jdk17' }

// 后台/小程序流水线
agent { label 'node18' }

// 抓取脚本流水线
agent { label 'python311' }

// 部署阶段（与构建分离，stage 级指定）
stage('Deploy Prod') {
  agent { label 'deploy' }
  when { branch 'main' }
  steps { input '确认部署生产?'; sh "./deploy/scripts/deploy.sh $IMAGE:$TAG $BRANCH_NAME" }
}
```

#### 18.9.3 清理与维护
- 每日凌晨 Job 清理 workspace 中 30 天未使用的构建目录。
- Docker 节点每周 `docker system prune -a --filter "until=168h"`。
- pnpm store 与 Maven 仓库保留（命中缓存），仅清理损坏文件。
